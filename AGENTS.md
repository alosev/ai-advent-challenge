# Контекст проекта

- LLM Console — консольное приложение на Go (модуль `llm-console`, go.mod: Go 1.22).
- Используется OpenAI-совместимый HTTP API; основной провайдер — DeepSeek.
- Общение и документация проекта — на русском.
- Настройки читаются из `config.json` в директории агента, выбранной через `--dir`
  при запуске или `/agent <директория>` в чате.
  Ключи API не добавлять в Git и не выводить при проверках.

## Архитектура

- `cmd/llm-console/main.go` — загрузка конфигурации, сборка зависимостей и запуск чата.
- `cmd/llm-console/args.go` — параметры запуска и справка.
- `cmd/llm-console/console.go` — интерактивный ввод и оформление вывода.
- `internal/app/ChatService` — сценарий диалога, контекст и общий расход токенов; не зависит от UI.
- `internal/history` — JSON-хранилище переписки и статистики токенов.
- `internal/memory` — отдельные JSON-хранилища рабочей памяти и долговременных facts.
- `internal/app/response_tool.go` — JSON Schema финального инструмента `submit_response`.
- `internal/app/memory_client.go` — инструкция автоматического обновления памяти
  и проверка аргументов `submit_response`. Ответ и изменения памяти приходят в одном
  вызове; его результат обратно модели не отправляем. Основные запросы используют
  `tool_choice: required` и `thinking: disabled`, без `response_format`.
  Суммаризация получает массив сообщений и возвращает обычный текст без инструментов;
  thinking отключён, настройки генерации основного чата не применяются.
  Повторных запросов для исправления нет.
- `internal/llm` — контракт клиента, модели сообщений и OpenAI-совместимый транспорт.
  `response_log.go` записывает только проблемные ответы API в локальный JSONL-лог:
  время, HTTP-статус, категорию проблемы и тело ответа. Данные конфигурации, запросов
  и HTTP-заголовки не логировать.
- `internal/tools` — инструменты `current_time`, `calculate`, `text_length`.
- `internal/config` — загрузка конфигурации.
- `cmd/llm-console/session.go` — сборка зависимостей и независимые сеансы агентов.
  `--dir` выбирает директорию при запуске, `/agent <директория>` переключает сеанс.
  У каждого агента свои настройки API, история, память, статистика и лог.
- `internal/profile` — единственный статичный профиль `profile` из конфигурации
  агента и его валидация.
- `internal/workflow` — конечный автомат необязательной задачи: процессы из
  конфигурации, активация startup/on_request, проверка переходов и JSON-хранилище.
- `internal/app/workflow.go` — команды задач, инструкция автоматической активации,
  инструменты `task_start`/`task_action` и проверка разрешений обычных инструментов.
  Пользовательские подтверждения модель выполнять не может. Рабочая память —
  контекст разговора с собственной целью и статусом, независимый от задачи workflow.
  Рабочая память не управляет автоматом; запуск, завершение, отмена и загрузка
  workflow не меняют и не очищают её автоматически. Временные сведения хранятся
  только в рабочей памяти; долговременная принимает profile.*, knowledge.*,
  decision.* и history.* без привязки к жизненному циклу workflow.
- `internal/app/profile.go` — просмотр `/profile` и системная инструкция профиля.
  Профиль не обновляется моделью и не участвует в суммаризации.

## Правила разработки

- **Тесты не пишем:** не добавлять новые тесты и не расширять существующие,
  если пользователь явно не изменит это правило.
- Обратную совместимость со старыми форматами и версиями не поддерживаем.
  Не добавлять миграции и legacy-ветки без явного запроса пользователя.
- Форматы файлов истории, памяти и других локальных данных не версионируем.
  Не добавлять поля `version`, номера версий формата и проверки версии при чтении
  без явного запроса пользователя. Читаем и записываем только текущую структуру;
  при загрузке проверяем содержимое данных, а не версию формата.
- Существующие тесты не удалять без отдельного запроса.
- Для проверки изменений использовать форматирование, сборку и при необходимости
  ручную проверку. Не обращаться к платному API без необходимости.
- Не записывать в документацию и ответы персональные абсолютные пути и сведения
  о локальном расположении SDK. Для файлов проекта использовать относительные пути.
