# LLM Console

Консольное Go-приложение для одного текстового запроса к LLM и вывода ответа.
Оно настроено на DeepSeek и использует его OpenAI-совместимый endpoint
`POST /chat/completions`.

## Запуск

1. Создайте файл конфигурации и внесите ключ. Он исключён из Git:

   ```bash
   cp config.example.json config.deepseek.json
   ```

   В `config.json` укажите `api_key`. Остальные поля уже настроены на DeepSeek.

2. Передайте запрос аргументом или введите его после запуска:

   ```bash
   go run ./cmd/llm-console "Объясни, что такое Go"
   go run ./cmd/llm-console
   ```

   Введите или вставьте текст, затем нажмите Ctrl+D на новой строке
   (в Windows — Ctrl+Z, затем Enter). Пустые строки сохраняются. Текст
   также можно передать через стандартный ввод:

   ```bash
   cat prompt.txt | go run ./cmd/llm-console
   ```

3. Проверка без обращения к API:

   ```bash
   go test ./...
   ```

## Настройки

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `api_key` | Ключ DeepSeek API | обязательно |
| `base_url` | Адрес OpenAI-совместимого API | `https://api.deepseek.com` |
| `model` | Идентификатор модели | `deepseek-flash` |
| `timeout_seconds` | Максимальное время HTTP-запроса | `60` |
| `reasoning_effort` | Уровень рассуждений модели, например `low`, `medium` или `high`; пустая строка — не передавать. Поддержка и значения зависят от провайдера и модели | не задан |
| `max_tokens` | Максимальное число токенов в ответе; `0` — не передавать ограничение | не задан |
| `temperature` | Управляет случайностью ответа: число от `0` до `2`; если поле отсутствует или равно `null`, используется значение провайдера. Поддержка зависит от модели | не задан |
| `thinking` | Режим thinking в DeepSeek: `enabled` или `disabled`; если поле отсутствует или пусто, используется настройка провайдера | не задан |
| `stop_sequences` | Последовательности, на которых нужно остановить генерацию | не задан |
| `response_schema` | JSON Schema требуемой структуры; включает JSON-режим | не задан |

Для DeepSeek задайте `"thinking": "disabled"`, чтобы `temperature` влияла
на ответ: в режиме thinking этот параметр игнорируется. Настройка thinking
передаётся в формате DeepSeek и может не поддерживаться другими провайдерами.
Если одновременно указан `reasoning_effort`, настройка `thinking`
имеет приоритет при выборе режима.

Если `response_schema` задана, приложение передаёт её в системной инструкции
и включает `response_format: {"type":"json_object"}`. Без схемы этот
параметр не передаётся и модель отвечает обычным текстом. Например,
конфигурация из `config.example.json` вернёт JSON следующего вида:

```json
{"answer":"..."}
```

JSON-режим гарантирует валидность JSON, но не соответствие JSON Schema. Не
задавайте `stop_sequences` для JSON-ответа без необходимости: остановка до
закрывающей фигурной скобки сделает JSON некорректным.

Пример содержит `"\n<END_OF_RESPONSE>"` как синтаксический пример
stop-последовательности. Для JSON-ответа удалите это поле: JSON должен
заканчиваться естественно. Stop-последовательность используйте для текстового
ответа без `response_schema`, предварительно попросив модель завершать ею
ответ.

Приложение использует только конфигурационный файл. По умолчанию это
`config.json`; путь можно указать явным аргументом:

```bash
go run ./cmd/llm-console --config /путь/к/config.json "Ваш вопрос"
```

## Архитектура

`cmd/llm-console` отвечает только за терминал. Сценарий запроса находится в
`internal/app/ChatService`; его можно вызвать из desktop-интерфейса без
копирования логики. Контракт `llm.Client` отделяет сервис от API-провайдера.
Чтобы добавить историю, следует реализовать репозиторий истории и подключить
его к `ChatService`, не меняя транспортный слой и UI.

После ответа расход токенов выводится в stderr: общее число, входные и выходные токены. Если провайдер не вернул статистику, выводится соответствующее сообщение.

## Инструменты модели

В каждый запрос передаются описания трёх локальных функций в формате
OpenAI-compatible `tools`. Модель сама решает, когда их вызвать:

- `current_time` — текущие дата и время в UTC, без аргументов;
- `calculate` — арифметика: `operation` (`add`, `subtract`, `multiply`,
  `divide`) и два числа `a`, `b`;
- `text_length` — количество кодовых точек Unicode в строке `text`.

При вызове инструмента его имя и аргументы выводятся в stderr до выполнения.
Итоговый ответ модели по-прежнему выводится в stdout.

Приложение проверяет аргументы, выполняет вызовы и отправляет результаты
обратно модели. Ошибки инструментов также передаются модели. Поддерживается
несколько вызовов за ответ; для одного пользовательского запроса ограничение —
10 обращений к API. Расход токенов суммируется по полученным ответам API.
Поддержка вызова инструментов зависит от выбранного провайдера и модели.
Пример: `go run ./cmd/llm-console "Сколько будет 123 умножить на 456?"`.
